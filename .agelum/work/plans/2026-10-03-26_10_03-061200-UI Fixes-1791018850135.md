## Current state / root causes of the "not smooth" hover

Current card classes (`how-it-works.tsx:27-34`):
- `transition-[transform,box-shadow] duration-500 ease-[cubic-bezier(0.22,1,0.36,1)] will-change-transform`
- `hover:-translate-y-1 hover:shadow-[0_16px_32px_-14px_...]`

Possible causes:
1. **Transition property mismatch (most likely).** Tailwind v4's `-translate-y-1` sets the CSS `translate` property, not `transform`. The card only transitions `transform` and `box-shadow`, so the lift snaps instantly while only the shadow eases. Fix by transitioning `translate` (or using the `transition-[translate,...]` form).
2. **Hover hit-area flicker.** The hover target is the element that moves. Near the card's bottom edge, the 4px lift moves the card out from under the cursor, which un-hovers it, then it drops back and re-hovers, so the card jitters. Fix by hovering on a stable wrapper (the `<li>`, which doesn't move on hover) and animating the inner card via `group-hover`.
3. **Animating `box-shadow` directly** repaints every frame. Cheaper: put the shadow on a pseudo-element or sibling layer and animate its `opacity`.
4. **Icon scale has a different duration** (700ms) from the card (500ms). The two motions finish at different times and feel disjointed. Align them.
5. The `<li>` already carries a scroll-driven `translate` (`.parallax-rise`, `globals.css:291,348`). Hover must stay on the inner card, not the `<li>`, so the two transforms don't fight. Hover state is read from the `<li>` through a group class.

## Phase 1 – Smooth the "Empezá simple" cards

File: `apps/landing/src/components/sections/how-it-works.tsx`

1. Line 22-26 (`<li>`): add the group class (`group/step`) so hover is detected on the stable wrapper. The `<li>` keeps `parallax-rise`. Don't add hover transforms to it.
2. Lines 27-34 (card div):
   - Remove the `group` class and `hover:` modifiers from the card. Use `group-hover/step:` and `group-hover/step:-translate-y-1`.
   - Change the transition list to `transition-[translate,box-shadow]`, with one shared duration and easing, for example `duration-500 ease-[cubic-bezier(0.22,1,0.36,1)]`.
   - Remove `will-change-transform` (or keep it only on hover) to avoid permanent layers.
   - Wrap hover styles in `motion-safe:` and `[@media(hover:hover)]:` so touch devices don't get sticky hover.
3. Lines 35-41 (icon `Image`): change the group selector to `group-hover/step:scale-105`, set the duration to 500ms to match the card, and use `transition-[scale]` (Tailwind v4 `scale-105` uses the `scale` property, so the same mismatch applies).
4. Optional shadow layer: if the shadow still looks steppy after 1-3, replace the animated `box-shadow` with an absolutely positioned `::after` carrying the final shadow, animated via `opacity`. Add a small reusable class in `apps/landing/src/app/globals.css` (near line 242, next to the other hover blocks), for example `.hover-lift`. Phase 2 reuses it.

## Phase 2 – Same hover on phone screenshots

Files:
- `apps/landing/src/components/phone-screenshot.tsx:23-39` (shared component)
- Call sites: `apps/landing/src/components/sections/hero.tsx:121-130`, `investor-experience.tsx:30-40`, `buyer-portal.tsx:37-47`

1. Implement the hover once, in `PhoneScreenshot`, so all three usages get it. Don't copy the classes per section.
2. Parent wrappers already own scroll-driven transforms: `.parallax-hero-phone` (translate + rotate, `globals.css:285,315`) and `.parallax-drift` (translate, `globals.css:290,343`). Apply the hover to an element inside those wrappers. Structure: an outer div (receives the caller's `className`, which carries the shadow and width), with the hover lift applied via `translate` and `transition-[translate,box-shadow]` on the same element that already has the `overflow-hidden rounded-[28px]` frame. If the existing `shadow-[...]` class passed in by callers makes the shadow transition awkward, move the shadow into the component and expose a prop, or use the opacity-layer approach from Phase 1 step 4.
3. Use the same lift (`-translate-y-1`, or slightly larger for the big phones), the same easing and duration, and the same `motion-safe:` and `hover: hover` guards as the cards. The hover must not move the layout or change the element's size.
4. The hero phone sits `absolute` over the dashboard card (`hero.tsx:121`). Confirm the hover lift doesn't clip against the parent. If it does, give the wrapper `overflow-visible`.
5. Keep the phone's hover area stable: put the hover trigger on the outer wrapper and animate the inner frame, to avoid the same flicker as cause 2.
