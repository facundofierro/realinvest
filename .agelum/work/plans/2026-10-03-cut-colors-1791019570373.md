# Plan: remove the purple/white "cut" at the hero → Problem boundary

Task: `.agelum/work/tasks/fixes/cut-colors.md`

## Certainty assessment

**Level: Medium-High**

The cause is located in code: the hero `DecorBlobs` container clips a blurred purple blob with `overflow-clip`, so the glow ends in a straight edge. Part of this was verified by reading the code. The part not verified visually is how much each of the three candidates (bottom blob, top-right blob, hero radial gradient) contributes to the edge while the parallax scroll animation is running. The plan therefore includes a small fallback (a mask fade) if the edge is still visible after the main fix.

## Ambiguity assessment

**Level: Low**

The request is to remove the purple gradient so the hero and the white section blend with no hard edge. The plan removes only the elements that produce the edge and keeps the rest of the hero's decoration (top-right glow, dot grid). "Remove the purple gradient" could also mean removing all purple from the hero, but the task text names the bottom blob as the cause, so this plan treats that as the scope. Any extra tint removal is a one-line follow-up.

## Root-cause analysis

Line numbers are the current ones. The task file's numbers are about one line off for the hero.

1. **Bottom blob clipped by container (main cause).** `apps/landing/src/components/sections/hero.tsx:93` has `{ className: "bottom-[-12%] left-[40%] size-[340px]", drift: -40 }`. It sits on the bottom edge of the hero. Its container in `apps/landing/src/components/decor-blobs.tsx:33` has `overflow-clip` and `absolute inset-0`, so the blur is cut at the container's bottom edge, which gives a hard horizontal line. The blob colour is `bg-[#D9B8EE]/40` (`decor-blobs.tsx:11`, index 1) with `blur-3xl` (`decor-blobs.tsx:42`).
2. **Container moves with the scroll animation.** The container has the class `parallax-hero-bg` (`hero.tsx:90`). The keyframes at `apps/landing/src/app/globals.css:286` (`translate: 0 30vh`) and the rules at `globals.css:320-322` and `380` move the whole container down on scroll. Its clip edge therefore moves too. The hero `<section>` only has `overflow-x-clip` (`hero.tsx:88`), so nothing clips it at the hero's bottom. The purple area can slide over the `Problem` section's top and still end in a straight edge.
3. **Hero background gradient (minor).** `hero.tsx:88` has `bg-[radial-gradient(900px_400px_at_85%_0%,#F3E8FA_0%,rgba(246,244,247,0)_70%)]`. It is anchored at the top right and fades to transparent by 70%. It is about 400px tall, so on a tall hero it should not reach the bottom. It only adds to the tint contrast at the top right.
4. **Top-right blob (minor).** `hero.tsx:92` has `{ className: "right-[6%] top-[14%] size-[420px]", drift: -40 }`. It moves down with the container, so after scrolling it could cross the container's lower edge.
5. **Next section has no tint.** `apps/landing/src/components/sections/problem.tsx:7` uses `Section` with no background. This is by design, so nothing should change here.

## Implementation steps

### Phase 1: Remove the bottom blob (the cut)

1. In `apps/landing/src/components/sections/hero.tsx:91-94`, delete the second blob entry (line 93, `bottom-[-12%] left-[40%] size-[340px]`). Keep the first (line 92).
2. `DecorBlobs` picks colours with `lightColors[i % lightColors.length]` (`decor-blobs.tsx:43`). With one blob left, the remaining blob stays at index 0 (`#EAD7F5/60`), so there is no colour change.
3. Do not change `decor-blobs.tsx` for this step. `launch-day.tsx:19` and `services.tsx:39` also use `DecorBlobs`, so edits there would affect those sections.

### Phase 2: Make sure no purple area can end in a straight line at the hero's bottom

1. In `hero.tsx:88`, change the radial gradient so it cannot reach the bottom edge. It is already limited to the top (`900px 400px at 85% 0%`) and ends in transparent, so leave it alone unless the edge is still visible after Phase 1.
2. Add a bottom fade to the hero `DecorBlobs` container only. Pass a class through the existing `className` prop at `hero.tsx:90`, for example `parallax-hero-bg [mask-image:linear-gradient(to_bottom,black_55%,transparent_100%)]`. The blobs and the dot grid then fade out before the container's bottom edge, so no hard line can appear even while the container moves on scroll.
3. Keep the `className` change local to the hero. Do not add the mask to the shared default in `decor-blobs.tsx:33`.

### Phase 3: Verify visually

1. Run the landing app and compare the hero/`Problem` boundary at scroll 0 and while scrolling through the hero (the `parallax-hero-bg` animation at `globals.css:286`). Check at a desktop width (md and up). The blobs are hidden below md (`decor-blobs.tsx:33`, `hidden … md:block`).
2. If a straight edge is still visible after Phases 1 and 2, remove the hero `radial-gradient` at `hero.tsx:88` as well and use the page background colour (`bg-background` or none, matching the surrounding sections).
