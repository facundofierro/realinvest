# Plan: Inventory building – remove double rounded card + animate windows

## Certainty assessment

**Level: Medium-High**

The "double-rounded card" cause is clearly located in code (nested rounded containers with mismatched backgrounds). The fix is small and low-risk. The animation part is less certain: the generation route (fal `image-to-video`) is feasible, but window-only flicker without the camera or geometry drifting is a model-behaviour risk that needs 1-4 prompt iterations and visual checks. A deterministic fallback (frame-based or masked overlay) exists.

## Ambiguity assessment

**Level: Low**

All key decisions were confirmed with the user (see Decisions made). The first request is clear. The second ("lightning in the windows, maybe changing window colors") leaves open: the delivery format (looping video vs. CSS/canvas overlay vs. animated WebP), whether it plays on load or on hover/in-view, and the `prefers-reduced-motion` behaviour. Also, "double-rounded car" is read as "double-rounded card" (see below). Only minor defaults remain (playback behaviour).

## Root cause (issue 1)

1. The image has an opaque background (≈ #EBE4ED) that doesn't equal the card's `bg-background` (hsl 280 17% 96% ≈ #F5F3F6), so the image reads as its own rounded rectangle inside the rounded card.
2. `rounded-2xl` on the image adds a second rounded outline inside the `rounded-3xl` card.
3. In dark mode the mismatch would be worse (light image on a dark card).

## Phase 1 – Single rounded container (white background, decided)

1. Regenerate the building on a pure white background with fal image edit: `genmedia run fal-ai/nano-banana-pro/edit --image_urls <uploaded inventory-building.webp> --prompt "Same isometric building, same colours, windows, trees and base. Replace the whole lilac background with a SOLID PURE WHITE #FFFFFF background, perfectly flat, no gradient/vignette; remove the cast floor shadow or keep it a very soft neutral grey." --output_format png --resolution 2K --aspect_ratio 1:1 --download ".imagegen/raw/inventory-building-white.{ext}"` (confirm the endpoint/params with `genmedia schema`). Verify visually: edges exactly #FFFFFF, building unchanged. Iterate on the prompt if the model alters the building. Fallback: chroma-key workflow from Agent Instructions, then composite onto white.
2. Save as `apps/landing/public/images/inventory-building.webp` (1200x1200, overwrite; clear `apps/landing/.next/cache/images` if stale).
3. `apps/landing/src/components/sections/inventory.tsx`: line 20 change `bg-background` to `bg-white` (dark mode: keep white card via `dark:bg-white` only if the dark theme is used; otherwise nothing), and remove `rounded-2xl` from the `Image` className (line 28). Result: one `rounded-3xl` bordered card with the building on white and no inner rounded box.

## Phase 2 – Window "lightning" animation

Generate with fal (`genmedia`), per Agent Instructions. Work in `.imagegen/` (prompts/raw/out, venv, add to `.gitignore`).

0. Model choice (decided: cheaper than the chosen model): use Kling image-to-video, find the current endpoint with `genmedia models "image to video kling" --category image-to-video` and compare `genmedia pricing`; Seedance is the alternative.
1. `genmedia upload apps/landing/public/images/inventory-building.webp` (the NEW white-background version, so the video background is white too) to get a CDN URL.
2. Write prompt file `.imagegen/prompts/inventory-anim.txt`, e.g.: *"Static locked-off camera. The isometric building does not move, rotate or change shape; the background, trees and base stay perfectly still. Only the window glass animates: soft flickers of light and gentle colour shifts (green, amber, blue, grey) ripple across windows at random, a few at a time, like lights switching on and off. No camera motion, no new objects, no text."* Negative prompt: camera movement, zoom, morphing, new objects.
3. Run `genmedia run <cheaper model> --image_url <url> --prompt "$(cat …)" --duration 5 --aspect_ratio 1:1 --download "raw/inventory-anim.{ext}" --async` (confirm params with `genmedia schema <endpoint>`). Poll with `genmedia status`.
4. Inspect result; iterate prompt (1-4 passes) until the building geometry is stable and only windows change.
5. Make it loop seamlessly: ffmpeg crossfade of the last ~0.5 s into the first frame (or ping-pong), crop/scale to 1200x1200 (or 800), encode `public/videos/inventory-building.webm` (VP9) and `.mp4` (H.264), no audio, small bitrate (<1.5 MB target). Keep `inventory-building.webp` as the poster.
6. Integrate in `inventory.tsx`: replace `Image` with a `<video autoPlay muted loop playsInline poster="/images/inventory-building.webp" preload="metadata">` with webm + mp4 `<source>`s, same sizing classes (`mx-auto block h-auto max-h-[440px] w-auto`), keep descriptive `aria-label`. Since the component is a server component, a small client wrapper (e.g. `components/inventory-video.tsx`, `"use client"`) is only needed if play/pause logic is wanted (see decisions).
7. Reduced motion: honour `prefers-reduced-motion` by not autoplaying (client wrapper reads `matchMedia`, shows poster only). Existing reduced-motion CSS lives at `globals.css:234-238`.

Fallback if the video model won't keep the geometry still: render 2-3 recoloured variants of the image (edit mode via `fal-ai/nano-banana-pro`, prompt "same image, only change window colours") and crossfade them with CSS keyframes (new `@keyframes windowShift` in `globals.css` next to line 221), or build a masked overlay from a window-mask PNG with `mix-blend-screen` and animated opacity.

## Decisions made

- Delivery: looping muted video (webm/mp4), current WebP as poster.
- Frame fix: ask the model to produce a white background (Phase 1), card set to white.
- Model: cheaper than Veo 3 (Kling image-to-video).
- Interpretation: "double-rounded car" = nested rounded card/frame around the image.

## Remaining minor choices (defaults applied, no blocker)

- Playback: autoplay loop only while in view (IntersectionObserver), poster only under `prefers-reduced-motion`.
