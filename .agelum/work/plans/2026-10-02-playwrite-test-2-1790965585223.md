## Certainty assessment

**Level: Medium-High**

All the use cases, the provider mocks and the UI copy the tests will assert on are in the code. The custody mock settles lazily on each read (`resolveDue`, `packages/fireblocks-mock/src/fireblocks-mock-provider.ts:47-63`). KYC decisions follow filename rules (`packages/providers-kyc/src/mock/rules.ts:13-52`). Auth uses an env-gated Credentials provider (`apps/wallet/src/auth.ts:15-58`). Research also turned up four real infrastructure problems the task does not mention. Each one blocks a deterministic suite, and each has a clear fix:

1. **The admin app reads an empty DB.** `apps/admin` has no `.env.local`. `createDb()` falls back to `file:./wallet.db` (`packages/db/src/client.ts:8`), which resolves to `apps/admin/wallet.db`, a 0-byte file with no tables. The admin CRUD tests cannot work until admin points at the same DB as the wallet (`apps/wallet/.env.local` → `DATABASE_URL=file:../../packages/db/wallet.db`).
2. **The local DB is behind on migrations.** `packages/db/wallet.db` records only 2 of the 5 migrations. It has no `trades` or `fireblocks_*` tables. That is why the last smoke run failed on `/exchange/VEX-ALAMOS-B3-522` (`apps/e2e/test-results/.last-run.json`). The suite must migrate before it seeds.
3. **The seed cannot reset state after an e2e run.** `packages/db/src/seed.ts:415-428` deletes `positions` and `users` but never `trades`. `trades` references `positions` and `users` with no cascade (`packages/db/src/schema.ts:233-239`), and the seed turns `PRAGMA foreign_keys = ON`, so a re-seed after any exchange fill fails. The seed also leaves the `fireblocks_*` tables alone, so custody balances and vaults from a previous run survive while the projection `balances` reset to 0.
4. **There is only one test identity.** The e2e Credentials provider always signs in `demo-user` (`apps/wallet/src/auth.ts:51-57`). The KYC none / pending / rejected / approved states are per user and only move forward (`kyc_applications.userId` is unique, `packages/providers-kyc/src/mock/mock-kyc-provider.ts:80-82`). With a single user, the "blocked" and "allowed" tests cannot both stay deterministic.

The remaining risk is ordinary UI-selector work on large client components (`exchange-page.tsx` is 1177 lines, `project-units-page.tsx` 740, `assets-page.tsx` 727). Some components will need `data-testid` or `aria-label` hooks. The `/project/:id/units` setState-in-render warning is not yet diagnosed (see Phase 0.5).

## Ambiguity assessment

**Level: Low**

The use-case list is explicit. On 2026-10-02 the user confirmed all four infrastructure decisions:

- **D1. Test identity and isolation: fresh `e2e-*` user per test.** The e2e Credentials provider accepts a `userId` (must start with `e2e-`) and creates the user on demand. Mutating tests each get a fresh user. `demo-user` is used only for read-only tests of seeded data.
- **D2. DB: the dev DB `packages/db/wallet.db`.** Global setup migrates and re-seeds it on every run, so local dev data is reset to the seed. `reuseExistingServer` keeps working. Document this in the README.
- **D3. States the UI cannot reach: DB helper in `apps/e2e/helpers/db.ts`** (`@libsql/client`). It flips `intended_outcome` on pending custody rows and sets `balances`. No test-only app routes.
- **D4. Fix the `/project/:id/units` setState-in-render bug in the app** and remove the fixme.
- **D5. Keep the real 15 s KYC auto-approve.** The pending test polls for up to 30 s, with no env override.

What remains is selector-level detail (exact copy strings and where to add `data-testid`), which the implementer resolves from the referenced files.

## Phase 0: Infrastructure fixes (prerequisites)

### 0.1 Make the seed a full reset (`packages/db/src/seed.ts:415-428`)
- Import `trades`, `kycApplications` and every `fireblocks*` table from `./schema`.
- At the top of the transaction, delete in FK-safe order: `trades`, then the existing `transactions`/`positions`/`holdings`/`balances`, then `kycApplications`, then the fireblocks tables (`fireblocksAssetOperations`, `fireblocksTransfers`, `fireblocksRampRequests`, `fireblocksDepositAddresses`, `fireblocksEligibility`, `fireblocksAccountFreezes`, `fireblocksBalances`, `fireblocksVaultAssets`, `fireblocksAssetPauses`, `fireblocksVaultAccounts`), then `sessions`/`accounts`/`users` and the catalog tables as today.
- This also removes `system-market-maker` and its vault. `getOrCreateMarketMaker` (`market-maker.ts:25-40`) re-creates them lazily. The `fireblocks-mock` and `providers-kyc` singletons keep no in-memory state beyond the DB (`apps/wallet/src/lib/custody.ts:8`, `apps/wallet/src/lib/kyc.ts:6`), so a re-seed while the dev servers run is safe.

### 0.2 Point the admin at the shared DB
- In `apps/e2e/playwright.config.ts`, add `env: { DATABASE_URL: <DB_URL> }` to the admin `webServer` entry. Do the same for the wallet entry (with `E2E_AUTH_BYPASS: "1"`).
- Compute `DB_URL` once in a shared `apps/e2e/env.ts`: `process.env.E2E_DATABASE_URL ?? "file:" + path.resolve(__dirname, "../../packages/db/wallet.db")` (decision D2: dev DB). Admin dev servers that are already running and were started without `DATABASE_URL` still point at the empty `apps/admin/wallet.db`. Global setup should detect this: call admin `/api/trpc/admin.dashboard.stats` (check the exact procedure path in `router.ts:21`) and fail with a hint to restart admin with `DATABASE_URL` or add `apps/admin/.env.local`.
- Recommend (README) adding `apps/admin/.env.local` with `DATABASE_URL=file:../../packages/db/wallet.db`. That file is gitignored, so document it rather than commit it. Optionally make `createDb` resolve its default relative to the package instead of the cwd. Do this only if the user wants it; it changes dev behavior.

### 0.3 Migrate + seed in global setup
- In `apps/e2e/global-setup.ts`, before the login, run (via `execSync` with `stdio: "inherit"` and `env: { ...process.env, DATABASE_URL: DB_URL }`):

- Note: Playwright starts `webServer` before `globalSetup`, so the seed runs against live servers. That is fine (see 0.1).
- Add an `E2E_SKIP_SEED=1` escape hatch for fast local iteration.
