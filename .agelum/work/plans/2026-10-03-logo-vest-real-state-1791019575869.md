# Plan: Show the full "Vest — REAL ESTATE" logo in the header

Task: `.agelum/work/tasks/fixes/logo-vest-real-state.md`

## Certainty assessment

**Level: Medium-High**

The code change is small and fully located. `BrandLogo` (`apps/landing/src/components/brand-logo.tsx:12-19`) hard-codes `showSubtitle={false}` and a viewBox cropped to the no-subtitle artwork. `VestLogo` already ships a ready-made `WITH_SUBTITLE` variant (`packages/ui/src/components/brand/vest-logo.tsx:27-32`) in which the "REAL ESTATE" path is already placed directly below the "est" wordmark. No new artwork is needed.

The remaining uncertainty is visual, not technical. The subtitle is very small (cap height ~7 of 200 units), so at the current 36px header height it would render at about 3-4px and be illegible. The logo has to be scaled up, and whether the result looks good in the 68px header can only be judged by looking at it. The task explicitly says to "evaluate how it looks".

## Ambiguity assessment

**Level: Low**

The task is clear: show the full logo with "REAL ESTATE" under the wordmark in the header, then evaluate it. The one decision with more than one reasonable answer is whether the footer and the mobile menu logo (same `BrandLogo` component) should change too. The default adopted in this plan is that all three change together, because it is the same brand lockup and keeping them consistent is the simplest option. To make the header the only place that changes, add a `showSubtitle` prop to `BrandLogo` (see Optional variant below). That is a trivial switch, so it does not need to block implementation.

## Root cause / why the subtitle is missing today

- `apps/landing/src/components/brand-logo.tsx:14` passes `showSubtitle={false}`, so `VestLogo` picks `WITHOUT_SUBTITLE` (`vest-logo.tsx:49-51`) and skips the subtitle `<path>` (`vest-logo.tsx:95-100`).
- `apps/landing/src/components/brand-logo.tsx:16` uses `viewBox="30 79 140 62"`. In the no-subtitle geometry the artwork spans y ≈ 81.4–139.3, so this crop is tight to the wordmark. Even if only `showSubtitle` were flipped, the viewBox would be wrong: the with-subtitle artwork occupies a different, higher y-range (≈ 67–141), so the top of the V would be cut off and the subtitle partly cropped.
- `aria-label` switches automatically to "Vest Real Estate" when `showSubtitle` is true (`vest-logo.tsx:61-65`).

## Implementation steps

### 1. Update `BrandLogo` (`apps/landing/src/components/brand-logo.tsx:12-19`)

- Remove `showSubtitle={false}` (line 14), or set it to `true`. The default in `VestLogo` is `true` (`vest-logo.tsx:45`).
- Change the viewBox (line 16) to crop to the with-subtitle artwork. Measured extents of `WITH_SUBTITLE` in the 200×200 box:
  - x: 32 (left edge of V) to 168 (right edge of "t" and the end of the subtitle)
  - y: 67.02 (top of the right V stroke, `vest-logo.tsx:29`) to ~141 (subtitle baseline, `vest-logo.tsx:31`)
  - Use `viewBox="30 65 140 78"`. This is 140 wide like today, which keeps the horizontal proportions, plus about 2 units of padding top and bottom.
- Update the docblock on line 4 so it no longer says the lockup is cropped without the subtitle.
- Increase the rendered height so the wordmark stays about the same size as today. Currently 62 viewBox units map to `h-9` (36px), about 0.58px/unit. 78 units at that scale is about 45px, so change `h-9` (line 17) to `h-11` (44px) or `h-[46px]`. The header has `min-h-[68px]` (`site-header.tsx:19`), so 44-46px fits without growing the header. If the subtitle still reads too small, try `h-12` (48px) and check that the header height is still acceptable.

### 2. Check the three consumers

- Header, desktop: `apps/landing/src/components/site-header.tsx:21` (inside the `<a aria-label="Real Invest — inicio">` link). No code change needed. Check vertical alignment against the nav items (`items-center`, line 19) and that the sticky header does not grow.
- Mobile menu: `site-header.tsx:58`. No code change needed. Confirm it fits in the sheet.
- Footer: `apps/landing/src/components/site-footer.tsx:16`, `<BrandLogo white className="mb-3" />`. With `forceWhite`, the subtitle uses `fill="white"` (`vest-logo.tsx:52-54, 98`), so it is legible on the dark band. `mb-3` plus the taller logo is fine, but check the spacing above the tagline at line 17.
- The `aria-label` on the header link (`site-header.tsx:20`) stays as is. The SVG's own label becomes "Vest Real Estate".

### 3. Optional variant (only if the footer/mobile logo should stay compact)

Add a `showSubtitle?: boolean` prop to `BrandLogo` (default `true`). Compute the viewBox from it: `"30 65 140 78"` with the subtitle, `"30 79 140 62"` without. Pass `showSubtitle={false}` from the call sites that should keep the compact logo. Skip this unless the visual evaluation shows that the footer or mobile logo looks worse.

### 4. Evaluate how it looks (required by the task)

- Run the landing app (`apps/landing`) and view the header at desktop and mobile widths, plus the mobile menu and the footer.
- Judge two things: whether the "REAL ESTATE" subtitle is legible at the chosen height, and whether the 44-48px logo crowds the 68px header.
- Record the outcome in the task or a summary note. If the subtitle is illegible at any reasonable header height, the fallback is to keep the subtitle-less logo in the header and use the full logo only in larger contexts such as the footer. That is the Optional variant above.
