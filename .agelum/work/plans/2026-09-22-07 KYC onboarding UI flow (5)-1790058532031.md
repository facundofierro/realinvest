# Plan: KYC onboarding UI flow

Task: `.agelum/work/tasks/pending/07 KYC onboarding UI flow (5).md`

## Certainty assessment

**Level: High**

The backing port (`@repo/providers-kyc`, built in task 06, already merged) is fully implemented, documented and exercised by nothing yet — so this task is purely additive wiring plus new UI, with no unknowns about persistence, migrations, or provider behavior. Every layer this task touches already has a working, close analog to copy from:

- Auth/session already carries `kycStatus` end-to-end (`apps/wallet/src/auth.ts:36-58`, `apps/wallet/src/types/next-auth.d.ts:1-18`) and native-token auth already round-trips it too (`apps/wallet/src/lib/native-auth.ts:11-55`) — no new auth plumbing needed, only reading `requireUser()`/`useCurrentUser()`.
- The GET-route → `lib/api/*.ts` → `getCurrentUserId()`/`getDb()` pattern is established and repeated 10+ times (e.g. `apps/wallet/src/app/api/wallet/balances/route.ts:1-12`, `apps/wallet/src/lib/api/wallet.ts:1-12`); the POST variant exists once (`apps/wallet/src/app/api/wallet/positions/route.ts:14-31`). The new `/api/kyc` route is a direct copy of this shape.
- `packages/ui` already ships `Form`/`FormField`/`FormItem` wired to `react-hook-form` + `zod` (`packages/ui/src/components/ui/form.tsx:1-178`), plus `Input`, `Label`, `Select`, `Checkbox`, `Textarea`, `Card`, `Dialog`, `Badge`, `Button` — enough primitives for every step; no new design-system components need to be built in `packages/ui` itself, only composed in `apps/wallet`.
- Page/route conventions (`p-4 space-y-6 animate-in fade-in slide-in-from-bottom-4`, back-arrow header, `(dashboard)` route group, thin `page.tsx` re-exporting a `components/pages/*-page.tsx`) are consistent across every existing screen (`apps/wallet/src/components/pages/deposit-page.tsx:1-76`, `apps/wallet/src/app/(dashboard)/deposit/page.tsx:1-6`).

All four decisions that were open in the first draft of this plan have been confirmed by the user (see "Confirmed decisions" below), so nothing in the approach remains a guess. Residual risks are purely mechanical, not research risk:
1. `zod`, `react-hook-form`, `@hookform/resolvers` are currently only declared in `packages/ui/package.json:26-48`, not in `apps/wallet/package.json`. Because `@repo/ui` is exported as raw `.tsx` source (`"exports": {"./components/ui/*": "./src/components/ui/*.tsx"}`, `packages/ui/package.json:5-9`) and transpiled inside the `apps/wallet` Next.js build, `apps/wallet` must declare its own direct dependency on these three packages (pnpm workspaces do not guarantee hoisting across packages). Fix: add to `apps/wallet/package.json`, `pnpm install`.
2. `@repo/providers-kyc` is not yet a dependency of `apps/wallet` and is not in `next.config.ts`'s `transpilePackages`. Same category of fix, mirroring how `@repo/db` was already added (`apps/wallet/next.config.ts:6`).

## Ambiguity assessment

**Level: Low**

The task's four steps ("personal identity data, document upload, beneficial owner declaration, PEP/sanctions declaration") and the status screen are unambiguous in outline. Four implementation decisions were not settled by the task text, the port, or existing code; all four were raised with the user and resolved before writing the steps below:

1. **Applicant-level PEP/sanctions self-declaration has no home in the port.** `KycSubmissionInput`/`KycIdentity` (`packages/providers-kyc/src/types.ts:16-42`) had no field for "is the applicant themselves a PEP / on a sanctions list" — only `BeneficialOwnerDeclaration.isPoliticallyExposed`, which describes a beneficial owner, not the applicant. **Confirmed:** extend `KycIdentity` with `isPoliticallyExposed`/`isSanctioned`, and have the mock auto-reject when either is `true` (Phase 0).
2. **Data-fetching/mutation pattern precedent.** `apps/wallet/src/hooks/use-queries.ts:1-98` wraps a legacy `@agelum/backend` reactive tRPC layer used by every already-migrated read, but has no working mutation anywhere yet (`useCreatePosition`/`useClosePosition` are stub `console.warn` functions). **Confirmed:** use `@tanstack/react-query`'s `useQuery`/`useMutation` directly against the plain `/api/kyc` REST route — this becomes the first real mutation in the app (Phase 3).
3. **Copy language scope.** The task says "Copy in Spanish/English consistent with existing screens," but every existing screen is 100% hardcoded Spanish with no i18n library anywhere in the repo. **Confirmed:** the KYC flow needs real bilingual support, scoped narrowly — a local ES/EN string dictionary plus a language toggle used only inside the new `components/kyc/*` files and the KYC page, with no new library, no locale routing, and no change to any existing (Spanish-only) screen (Phase 4).
4. **Navigation entry points / forced-onboarding scope.** **Confirmed:** status-aware CTAs in the account dialogs (`bottom-nav.tsx`, `desktop-top-nav.tsx`) plus a dashboard banner are sufficient; no forced redirect to `/kyc` after login (that remains gating's territory — task 08).

No open decisions remain that would need a human call mid-implementation.

    ```ts
    import { z } from "zod";

    export const kycIdentitySchema = z.object({
      fullName: z.string().min(3),
      dateOfBirth: z.string().min(1), // YYYY-MM-DD from <input type="date">
      nationality: z.string().min(1),
      documentType: z.string().min(1),
      documentNumber: z.string().min(3),
      address: z.string().optional(),
      isPoliticallyExposed: z.boolean(),
      isSanctioned: z.boolean(),
    });

    export const kycDocumentSchema = z.object({
      type: z.enum(["government_id", "proof_of_address", "selfie", "beneficial_owner_declaration", "other"]),
      fileName: z.string().min(1),
      uploadedAt: z.string().min(1),
    });

    export const beneficialOwnerSchema = z.object({
      fullName: z.string().min(3),
      documentNumber: z.string().min(3),
      ownershipPercentage: z.number().min(0).max(100),
      isPoliticallyExposed: z.boolean(),
    });

    export const kycSubmissionSchema = z.object({
      identity: kycIdentitySchema,
      documents: z.array(kycDocumentSchema).min(4), // ID front, ID back, selfie, proof of address
      beneficialOwners: z.array(beneficialOwnerSchema).default([]),
    });

    export type KycSubmissionFormValues = z.infer<typeof kycSubmissionSchema>;
    ```

11. Create `apps/wallet/src/app/api/kyc/route.ts`:
    ```ts
    import { NextResponse } from "next/server";
    import { getKycApplication, submitKycApplication } from "@/lib/api";
    import { requireUser, unauthorizedResponse } from "@/lib/api-auth";
    import { kycSubmissionSchema } from "@/lib/kyc-schema";

    export const runtime = "nodejs";
    export const dynamic = "force-dynamic";

    export async function GET() {
      if (!(await requireUser())) return unauthorizedResponse();
      const application = await getKycApplication();
      return NextResponse.json({ application });
    }

    export async function POST(request: Request) {
      if (!(await requireUser())) return unauthorizedResponse();
      const body = await request.json().catch(() => null);
      const parsed = kycSubmissionSchema.safeParse(body);
      if (!parsed.success) {
        return NextResponse.json({ error: "Invalid submission", issues: parsed.error.issues }, { status: 400 });
      }
      const application = await submitKycApplication(parsed.data);
      return NextResponse.json({ application });
    }
    ```

    ```ts
    // KYC API
    export async function getKycApplication(): Promise<KycApplication | null> {
      const res = await fetch(getApiUrl("/api/kyc"));
      if (!res.ok) throw new Error("Failed to fetch KYC application");
      const data = await res.json();
      return data.application ?? null;
    }

    export async function submitKyc(input: KycSubmissionInput): Promise<KycApplication> {
      const res = await fetch(getApiUrl("/api/kyc"), {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(input),
      });
      if (!res.ok) throw new Error("Failed to submit KYC application");
      const data = await res.json();
      return data.application;
    }
    ```

    ```ts
    const KYC_QUERY_KEY = ["kyc", "application"] as const;

    // KYC (plain TanStack Query — this domain has no reactive/tRPC route)
    export function useKycApplication() {
      return useQuery({

      });
    }
    ```

    ```tsx
    "use client";

    import { createContext, useContext, useEffect, useState } from "react";
    import { kycCopy, type KycLocale } from "@/lib/kyc-copy";

    const STORAGE_KEY = "kyc-locale";
    const KycLocaleContext = createContext<{ locale: KycLocale; setLocale: (l: KycLocale) => void } | null>(null);

    export function KycLocaleProvider({ children }: { children: React.ReactNode }) {
      const [locale, setLocale] = useState<KycLocale>("es");

      useEffect(() => {
        const stored = window.localStorage.getItem(STORAGE_KEY);
        if (stored === "es" || stored === "en") setLocale(stored);
      }, []);

      const update = (l: KycLocale) => {
        setLocale(l);
        window.localStorage.setItem(STORAGE_KEY, l);
      };

      return (
        <KycLocaleContext.Provider value={{ locale, setLocale: update }}>{children}</KycLocaleContext.Provider>
      );
    }

    export function useKycCopy() {
      const ctx = useContext(KycLocaleContext);
      if (!ctx) throw new Error("useKycCopy must be used within KycLocaleProvider");
      return { copy: kycCopy[ctx.locale], locale: ctx.locale, setLocale: ctx.setLocale };
    }
    ```

## Explicitly out of scope for this task

- Gating `invest`/`deposit`/`withdraw`/`exchange` on KYC status (server 403s, blocked-feature dialogs) — task 08.
- Real file/blob storage for uploaded documents — the port only ever persists `{type, fileName, uploadedAt}` (task 06's explicit design, restated in its README).
- Any change to `packages/db` schema/migrations — the new applicant-level fields (Phase 0) fit inside the existing untyped JSON `identity` column.
- An app-wide i18n framework or locale-routed pages — bilingual support is a small dictionary + toggle scoped only to the new `components/kyc/*` files and the `/kyc` page; every other existing screen keeps its current hardcoded Spanish text unchanged.
- Forced redirect of unverified users to `/kyc` immediately after login — only opt-in entry points (account-menu CTA, dashboard banner) are built.
