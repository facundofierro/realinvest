# Plan: Playwright smoke tests for admin and wallet apps

Task: `.agelum/work/tasks/doing/playwrite-test.md`

## Certainty assessment

**Level: Medium-High**

The scope is well bounded (visit about 16 routes, fail on page errors, console errors or non-2xx). The routes, ports and layouts are all located in the code. The one real risk is wallet authentication, now handled by an env-gated bypass. `apps/wallet/src/proxy.ts:4-20` and `apps/wallet/src/app/(dashboard)/layout.tsx:10` redirect unauthenticated users to `/login`. Login is Google OAuth only (`apps/wallet/src/auth.ts:38`), so a test cannot log in through the UI. Following the user's direction, the plan adds an `E2E_AUTH_BYPASS` env flag that enables a Credentials provider in `apps/wallet/src/auth.ts`, so Auth.js itself issues a genuine session cookie and no cookie forging is needed. I have not run this against `next-auth@5.0.0-beta.32`. The main detail to verify is that Credentials works with `strategy: "jwt"` and the `jwt` callback at `auth.ts:47-60`. Console noise from existing code (hydration warnings, failed image or font loads, 401s from `/api/*`) may also force an allowlist once the suite first runs.

## Ambiguity assessment

**Level: Low**

The task is clear, and the main open decision (wallet auth) was settled by the user: use an env variable to bypass OAuth. The remaining items are minor defaults. If you disagree with one, say so before implementation starts.

1. **Ports are stale in the task.** The task says admin is on `8001`. The real ports are admin `47311` and wallet `47310` (`apps/admin/package.json:6`, `apps/wallet/package.json:6`). Default: use those.
2. **Placement.** Default: a new workspace package `apps/e2e` (it matches the `apps/*` glob in `pnpm-workspace.yaml:2`), rather than a root-level `tests/` folder. This keeps Playwright out of the root `package.json`.
3. **Wallet auth (decided by the user).** Use an env variable, `E2E_AUTH_BYPASS=1`, that bypasses the Google OAuth login when running e2e tests. Implementation default: a dev-only Credentials provider (see Phase 3). It is refused when `NODE_ENV === "production"`.
4. **Prerequisites.** Default: the tests assume a seeded DB (`pnpm db:seed`). The tests do not seed the DB themselves.
5. **Base URL.** Default: `http://localhost:<port>`. This avoids Caddy and TLS (see memory `local-caddy-proxy`). `AUTH_URL` points at the Caddy HTTPS domain, so check that the credentials callback and cookie work on localhost. `trustHost: true` is set at `apps/wallet/src/auth.ts:42`. If the cookie is `Secure`-prefixed, point `WALLET_URL` at the Caddy domain instead.

## Phase 1: e2e workspace package

1. Create `apps/e2e/package.json`:
   - `name: "e2e"`, `private: true`.
   - Scripts: `"test": "playwright test"`, `"test:admin": "playwright test --project=admin"`, `"test:wallet": "playwright test --project=wallet"`, `"install:browsers": "playwright install chromium"`.
   - devDependencies: `@playwright/test`, `@types/node`, `typescript`.
2. Create `apps/e2e/tsconfig.json` (a minimal config for the tests and the Playwright config).
3. Run `pnpm install` so that `pnpm-lock.yaml` is updated.
4. Add an `e2e` script to the root `package.json`: `"e2e": "pnpm --filter e2e test"`.
5. Do not wire `e2e` into `turbo run test` (`turbo.json:30`). It needs live servers and a browser. Leaving it out keeps `pnpm test` fast and deterministic. Note this decision in the README.

## Phase 2: Playwright config

Create `apps/e2e/playwright.config.ts`:

- Env-overridable base URLs. Defaults: `ADMIN_URL=http://localhost:47311`, `WALLET_URL=http://localhost:47310`.
- `webServer`: two entries that run `pnpm --filter admin dev` and `pnpm --filter wallet dev`. Each has `url` set to its base URL, `reuseExistingServer: !process.env.CI` and `timeout: 120_000`.
- `globalSetup: "./global-setup.ts"`.
- `projects`:
  - `admin`: `testMatch: /admin\.spec\.ts/`, `use.baseURL = ADMIN_URL`.
  - `wallet`: `testMatch: /wallet\.spec\.ts/`, `use.baseURL = WALLET_URL`, `use.storageState = ".auth/wallet.json"`.
- `use`: Desktop Chrome, `trace: "retain-on-failure"`, `screenshot: "only-on-failure"`.
- `timeout`: 60s per test (the first dev compile of each route is slow). `workers: 1` or limited, so that `next dev` is not overloaded.
- Add `.auth/`, `test-results/` and `playwright-report/` to `.gitignore`. Alternatively, add a local `apps/e2e/.gitignore`.

## Phase 3: Wallet auth bypass via env variable

**3a. App change, `apps/wallet/src/auth.ts`.**

1. Define `const e2eBypass = process.env.E2E_AUTH_BYPASS === "1" && process.env.NODE_ENV !== "production";`. Log a `console.warn` when it is active.
2. Change `providers: [Google]` (`auth.ts:38`) to `providers: e2eBypass ? [Google, Credentials({ id: "e2e", credentials: {}, authorize: async () => { ...select the user with id "demo-user" via getDb()/users; return { id, name, email } or null } })] : [Google]`. Import `Credentials` from `next-auth/providers/credentials`.
3. The `jwt` callback (`auth.ts:47-60`) already copies `user.id` into the token and loads `kycStatus` on sign-in, so it needs no change. Credentials works with `session: { strategy: "jwt" }`, which is already set (`auth.ts:41`). The DrizzleAdapter is not used for the credentials flow.
4. Do not touch the gates (`proxy.ts:4-20`, `(dashboard)/layout.tsx:10`). They keep working against a real session cookie, so the tests exercise the same path as a real user.
5. Add `E2E_AUTH_BYPASS` to `globalEnv` in `turbo.json:3-15` (only if turbo should pass it through).

**3b. Test side, `apps/e2e/global-setup.ts`.**

1. Fetch `${WALLET_URL}/api/auth/csrf` with a request context (`request.newContext`) to get `csrfToken` (the cookie jar keeps the csrf cookie).
2. POST `${WALLET_URL}/api/auth/callback/e2e` as form data with `csrfToken` and `callbackUrl=/` (`redirect: manual` is fine).
3. Save `context.storageState({ path: ".auth/wallet.json" })`. Throw a clear error if no `authjs.session-token` cookie is present, or if `GET /api/auth/session` returns no `user.id`.
4. The `webServer` entry for the wallet in `playwright.config.ts` must set `env: { E2E_AUTH_BYPASS: "1" }`. Because `reuseExistingServer` is on, a manually started dev server must also be launched with `E2E_AUTH_BYPASS=1`. Document this in the README, and have global setup fail with that hint if the callback is rejected.
5. The `demo-user` row must exist (`pnpm db:seed`, `packages/db/src/seed.ts:42,393`).

Remove the earlier idea of forging the JWT with `@auth/core/jwt` (`AUTH_SECRET` is no longer needed in the test package, and the `dotenv` load of `../wallet/.env.local` is not needed for auth).

## Phase 4: Shared helper and specs

1. Create `apps/e2e/helpers/smoke.ts` with `expectPageRenders(page, path)`:
   - Attach `page.on("pageerror")` and `page.on("console")` listeners (the latter for `type() === "error"`). Collect messages that do not match an `IGNORED_CONSOLE` allowlist. The allowlist starts empty and gets filled only with specific, commented patterns after the first run (for example, third-party image 404s).
   - Record failed same-origin responses with `page.on("response")`, where status >= 400 and the URL is under `/api/` or is a document request. Ignore `_next` HMR and favicon noise.
   - `const res = await page.goto(path, { waitUntil: "domcontentloaded" })`. Assert `res.ok()` (non-2xx fails with a message that includes the status and URL). Then `await page.waitForLoadState("networkidle")`, and assert `page.locator("body")` is visible.
   - Assert that the final URL is not `/login` for wallet routes (this catches auth failures that would otherwise look like a 200).
   - Assert that the Next.js error overlay is absent. Check for `nextjs-portal` or the text "Application error: a client-side exception has occurred".
   - At the end, `expect(errors, errors.join("\n")).toEqual([])`.
2. `apps/e2e/admin.spec.ts`: iterate over `["/", "/properties", "/chat", "/activity"]`, with one `test()` per route.
3. `apps/e2e/wallet.spec.ts`: routes `/`, `/assets`, `/chat`, `/deposit`, `/exchange`, `/exchange/VEX-ALAMOS-B3-522`, `/invest`, `/kyc`, `/tokenization`, `/withdraw`, `/project/torre-libertador-8000`, `/project/torre-libertador-8000/units`. The task suggests placeholder ids like `1` and `BTC`, but the fixtures use slug ids and the seeded symbols above. Using real ids avoids false failures from a "not found" state. Keep the ids as constants at the top of the spec.
4. Add one navigation test per app. Start at `/`, then click each main nav link (admin: `admin-desktop-nav.tsx:25-35`; wallet: `nav-items.ts:15-33`), and assert that the URL changes and that no errors occur. This covers the "menus and submenus" wording of the task. The route-by-URL tests remain the main coverage. Note that `/invest` and `/exchange` are `blocked: true` in `TOP_MAIN_ITEMS` (`nav-items.ts:30-31`) and open a launch-notice dialog when clicked on desktop, so assert the dialog appears for those two links. Alternatively, run the nav test at a mobile viewport, where the bottom nav links through (`bottom-nav.tsx:120`).
5. If a route has a pre-existing, unrelated app error when first run (for example `/kyc` gating), do not hide it with a broad allowlist. Use `test.fixme` with a comment that links the cause, so the failure stays visible.
