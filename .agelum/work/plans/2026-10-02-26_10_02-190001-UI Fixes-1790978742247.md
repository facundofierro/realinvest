## Possible root causes / reasons for the current state

- The coin was deliberately prompted as violet to match the brand, and the prompt forbids symbols, so it does not read as "bitcoin" or gold.
- The four payment icons are flat SVG line glyphs from `icons.tsx` (26px inside a 52px tile). This was a cheap placeholder and has no depth or quality.

## Phase 1: Golden bitcoin coin (Annotation 1)

1. Edit `.imagegen/prompts/payments-coin.txt`:
   - Change "coin body in deep violet (#5B1187) with a polished gold rim" to a coin that is entirely polished metallic gold with a slightly darker gold rim and warm highlights.
   - Replace the hexagon-pattern text with a bold embossed ₿ (Bitcoin B with two vertical strokes) on the face. This is a symbol, not a letter. Update the blanket "no symbols" rule to allow only this one emblem, and keep "no other text, letters, numbers or logos".
   - Keep the green #00FF00 key block verbatim, including the no-reflection, no-flare, no-outline and no-shadow rules. Gold has no green in it, so the green key is safe.
2. Run `.imagegen/gen payments-coin 1:1`, then `.imagegen/cut payments-coin 336`. Read `.imagegen/out/payments-coin.webp` and check for green fringe, the ₿ shape, and centering. Iterate on the prompt one fix at a time.
3. Run `.imagegen/deploy payments-coin`. No code change is needed, as the filename stays the same. If the browser or Next optimizer serves stale bytes, `curl` the static file and `rm -rf apps/landing/.next/cache/images`.
4. Optionally check the coin against the `bg-tint` card (#EFE3F8-ish) background for contrast. Gold on lilac should be fine.

## Phase 2: 3D images for the 4 payment cards (Annotation 2)

1. Create four prompt files in `.imagegen/prompts/`, each in the same 3D soft-clay/glossy style, brand violet (#5B1187) with pink accents and gold highlights, on the green #00FF00 key background with the same boilerplate constraints as the coin prompt:
   - `payment-cards.txt`: a credit card, slightly tilted, with a chip, blank (no numbers or text).
   - `payment-qr.txt`: a phone or tile with an abstract blocky QR-like pattern next to a wallet (no real readable code).
   - `payment-transfer.txt`: a classical bank building with columns, 3D.
   - `payment-abroad.txt`: a 3D globe with abstract continents and a subtle orbit ring.
2. For each, run `.imagegen/gen <name> 1:1`, then `.imagegen/cut <name> 256` (the larger size keeps it sharp at 2x DPR). Inspect each output and iterate until clean. Keep a consistent camera angle, lighting and palette across the set.
3. Run `.imagegen/deploy` for each, producing `apps/landing/public/images/payment-{cards,qr,transfer,abroad}.webp`.
4. Update `apps/landing/src/components/sections/payments.tsx`:
   - Replace the `icons` map (lines 7-12) with a map from point key to image path.
   - Replace line 27 with `<Image src={images[point.key]} alt="" width={72} height={72} className="mb-4 size-[72px]" />`, with no tinted tile, so the 3D object stands on the card. Remove the unused `IconTile` and `IconName` import (line 2). Keep `Image`, which is already imported.
   - Do not touch `icons.tsx`, since other sections use it.
5. Check responsive layout. The grid is `sm:grid-cols-2 lg:grid-cols-4` (line 24), and the larger image only adds ~20px of height.
