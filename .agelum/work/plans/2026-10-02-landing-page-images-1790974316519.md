# Plan: Generate landing page images (`apps/landing`)

Task: `.agelum/work/tasks/fixes/landing-page-images.md`

## Certainty assessment

**Level: Medium**

The code side is well understood: every illustration slot, its wrapper section and its layout constraints are located (see "Slot inventory"), and wiring raster images via `next/image` from a new `apps/landing/public/images/` folder is routine. Uncertainty is concentrated in (a) the generation step — the `@agent:image` agent (genmedia / fal.ai) is not defined in this repo (`.claude/agents` does not exist, `.agelum/ai/*` folders are empty), so the exact tool/model/credentials (`FAL_KEY`) are unverified; and (b) which illustrations should actually be replaced. Generative models render legible UI text/numbers poorly, so replacing the UI mocks would likely regress quality; the plan therefore proposes complementing, not replacing, them. That recommendation needs the user's confirmation.

## Ambiguity assessment

**Level: Medium-Low**

User decisions (2026-10-02): **replace all** SVG illustrations with generated images; **mixed** style (photoreal for buildings/people/places, stylised 3D/isometric for abstract concepts); **people allowed, sparingly**; generation via `@agent:image` (genmedia / fal.ai) — "if it fails, stop and tell me". Remaining small decisions are defaulted in this plan (see "Defaults taken"); none should block starting.

Residual risk: AI models cannot render legible UI text/numbers, so replaced "UI mock" slots become *conceptual* images with text kept in HTML overlays/captions (see Phase 2). If the user expected pixel-accurate product screenshots in those slots, they should say so.

### Defaults taken
- Images are committed to `apps/landing/public/images/` as WebP.
- No text, logos, or numbers inside generated images; all copy stays in HTML (`es.ts`), preserving the copy rules and the "Datos de ejemplo" labelling.
- People: at most 2 images (services setup, buyer portal/hero), faces not in close-up, diverse adults, no testimonial framing.
- Small icon set (`illustrations/icons.tsx:116`) and the 84px `CryptoCoin` are icons, not illustrations: `CryptoCoin` is replaced by a stylised 3D coin image; the `IconTile` icon set stays SVG.
- If the image agent/`FAL_KEY` fails: stop and report to the user (do not fall back to other tools).

## Context / findings

- `apps/landing` is Next 16.1.1 (`apps/landing/package.json`), `output: "standalone"` (`apps/landing/next.config.ts:4`). No `public/` dir exists, so no raster images today. `next/image` works with standalone; `sharp` is auto-used by Next in standalone builds, no config needed for local images.
- Metadata (`apps/landing/src/app/layout.tsx:17-27`) has `openGraph` with no `images` → no OG/social preview image. Can use file convention `src/app/opengraph-image.png` (+ `twitter-image.png`) instead of editing metadata.
- Copy rules (`apps/landing/src/content/es.ts:1-6`): no yield/return promises, no tokenization/marketplace/founders content, "comprador" wording. Image prompts must not imply returns, crypto-trading, or invented real projects. Existing sample data is labelled "Datos de ejemplo" (`es.ts:17`); generated imagery must not contain readable text, logos, or numbers (models garble them; avoids misleading claims).
- Palette (`apps/landing/src/app/globals.css:16-37`): ground `#F6F4F7`, ink `#2A1634`, brand `#5B1187`, accent pink `#D6336C`, soft lilac `#EAD7F5`. Prompts should push toward this palette for cohesion.

Confirm the `@agent:image` agent (genmedia / fal.ai) works with a single test generation. If it errors (missing agent, missing `FAL_KEY`, quota), **stop and tell the user**.

## Phase 1 — Prepare and generate

1. Create `apps/landing/public/images/` (does not exist).
2. Write the prompt sheet `.agelum/doc/docs/plan/landing-images-prompts.md`: per image → filename, slot, aspect, style (photoreal | stylised), prompt, model, seed. Shared blocks:
   - Palette: *"muted violet and lilac colour grade (#5B1187, #EAD7F5, #2A1634), subtle pink accent (#D6336C), soft diffused light"*.
   - Photoreal: *"photorealistic, architectural photography, modern residential tower, natural light, shallow depth of field"*.
   - Stylised: *"soft 3D isometric render, clay/matte materials, rounded forms, studio lighting, plain lilac background"*.
   - Always: *"no text, no letters, no numbers, no logos, no watermark, no signage"*; people: *"adults, diverse, natural candid, not looking at camera, no close-up faces"*.
   - Copy rules (`es.ts:1-6`): no imagery implying yields/returns/crypto trading (coin is a neutral stylised object), no invented real brand names.
3. Image list & sizes (generate 2–3 candidates each, keep best):
   `hero.webp` 4:5 (1000×1250) · `problem-before.webp` 4:3 (960×720) · `problem-after.webp` 4:3 · `inventory-building.webp` 1:1 (1200×1200) · `buyer-portal.webp` 4:5 (1000×1250) · `investor-experience.webp` 4:3 (1200×900) · `trust-loop.webp` 3:1 (1500×500) · `buyers-reactivation.webp` 4:3 · `payments-coin.webp` 1:1 (336×336, transparent or lilac bg) · `launch-day.webp` 21:9 (1800×770) · `service-setup.webp`/`service-3d.webp`/`service-crm.webp` 3:2 (960×640) · `final-cta-skyline.webp` 12:5 (1920×800) · `opengraph-image.png` 1200×630.
