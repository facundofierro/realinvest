3. Both sections share almost the same background (hero radial gradient fades into `bg-background`), so there is no
   visual separator either.

## Implementation

### General technique (applies to every phase)

- **Primary engine: CSS scroll-driven animations** (`animation-timeline: scroll()` / `view()`), transform/opacity only.
  Chrome/Edge ≥115 and Safari ≥26 support them; Firefox does not (flag only).
- Every scroll-driven rule lives inside:
  ```css
  @supports (animation-timeline: view()) {
    @media (prefers-reduced-motion: no-preference) { … }
  }
  ```
  so reduced-motion users and unsupported browsers get the static layout (which must look correct on its own).
- Use `animation: <name> linear both; animation-timeline: …; animation-range: …;`.
  Note: `animation-timeline` must be declared **after** the `animation` shorthand (the shorthand resets it).
- **Never put a scroll-driven transform on an element that already has a transform/animation** (e.g. the hero
  `animate-fade-in-up` wrapper `hero.tsx:82`, hover `-translate-y` cards in `payments.tsx:29`, `how-it-works.tsx:27`,
  `.badge-carousel > *:hover` in `globals.css:248-251`). Add a wrapper `div` and animate the wrapper instead.
- Use the individual `translate` / `scale` / `rotate` CSS properties in parallax keyframes (not `transform`) where an
  element might also get a Tailwind transform — they compose instead of overwriting.
- Put all new CSS in a new block at the end of `src/app/globals.css` titled `/* ---- Parallax ---- */`, with
  semantic class names (`.parallax-*`). Do not invent Tailwind arbitrary-property soup in JSX for these.
- Distances: subtle (≤ 60px for in-section drifts) so text readability and click targets are unaffected.
- Mobile: see Phase 0 decision; default = in-section drifts only from `md:` (≥768px), hero gap effect on all sizes.

### Phase 0 — Shared plumbing

1. **`src/app/globals.css`** (append at the end, after `:257`):
   - Keyframes used by later phases:
     ```css
     @keyframes parallax-hero-out   { to   { translate: 0 var(--hero-drift, 18vh); opacity: .35; scale: .97; } }
     @keyframes parallax-gap-close  { from { translate: 0 var(--gap-close, 14vh); } }
     @keyframes parallax-drift      { from { translate: 0 var(--drift, 40px); } to { translate: 0 calc(var(--drift, 40px) * -1); } }
     @keyframes parallax-rise       { from { translate: 0 var(--rise, 60px); } }
     @keyframes parallax-zoom       { from { scale: 1.12; } to { scale: 1; } }
     @keyframes parallax-pan        { from { object-position: var(--pan-from, 50% 0%); } to { object-position: var(--pan-to, 50% 100%); } }
     ```
   - Generic helper classes (each inside the `@supports` + `prefers-reduced-motion: no-preference` guard):
     - `.parallax-drift` → `animation: parallax-drift linear both; animation-timeline: view(); animation-range: cover 0% cover 100%;`
       Speed controlled per element with `style={{ "--drift": "30px" }}` (negative values = moves the other way).
     - `.parallax-rise` → `parallax-rise`, `view()`, `animation-range: entry 0% cover 40%`.
     - `.parallax-zoom` → `parallax-zoom`, `view()`, `animation-range: entry 0% cover 50%`.
   - Wrap the drift/rise helpers in `@media (min-width: 768px)` (mobile = static, per decision).
2. **(Only if the JS fallback is selected — see Decisions)** create `src/components/scroll-progress.tsx` (`"use client"`):
   - On mount: return early if `CSS.supports("animation-timeline: scroll()")` or reduced motion matches.
   - Otherwise attach a passive `scroll` listener + `requestAnimationFrame` throttle that writes
     `document.documentElement.style.setProperty("--hero-p", String(Math.min(1, scrollY / innerHeight)))`.
   - Render `null`. Mount it once in `src/app/page.tsx` next to `<SiteHeader />` (`:30`).
   - In CSS add an `@supports not (animation-timeline: scroll())` block that maps `--hero-p` onto the two hero

### Phase 1 — First load shows only the hero; gap closes while scrolling (the user's main request)

Goal: at scroll 0 the viewport shows the hero only, with generous empty space below it; as the user scrolls, the
hero content lags behind (slower) and `Problem` catches up (faster), so the visual gap shrinks to roughly the
current spacing by the time `Problem` reaches the top half of the viewport.

1. **Make the hero fill the first viewport** — `src/components/sections/hero.tsx:62-63`:
   - `<section>`: add `relative flex min-h-[calc(100svh-68px)] flex-col justify-center` (68px = sticky header,
     `site-header.tsx:19`). Keep the gradient. Keep `pt-14 md:pt-[88px] pb-[72px]` as minimum padding so short
     viewports / mobile (where content is taller than the screen) still behave like today.
   - Add `overflow-x-clip` (not `overflow-hidden`, to keep the phone shadow / later drift from being cut vertically).
   - Result: on desktop `Problem` starts exactly at the fold → nothing of section 2 is visible on load.
2. **Hero content moves slower and fades slightly as it leaves** — wrap the existing grid `div` (`hero.tsx:63`) in
   (or add to it) class `parallax-hero-out`:
   ```css
   .parallax-hero-out {
     animation: parallax-hero-out linear both;
     animation-timeline: scroll(root);
     animation-range: 0 100svh;   /* lengths are valid ranges for scroll() timelines */
   }
   ```
   `--hero-drift: 18vh` → content scrolls at ~0.8× page speed; opacity 1 → .35; scale 1 → .97.
   Must not be the same element as `animate-fade-in-up` (`hero.tsx:82`) — that one is a child, fine.
3. **Problem section catches up** — `src/components/sections/problem.tsx:7`:
   - Add `relative z-[1] parallax-gap-close` to the `Section` `className`:
     ```css
     .parallax-gap-close {
       animation: parallax-gap-close linear both;
       animation-timeline: scroll(root);
       animation-range: 0 70svh;
     }
     ```
     Starts translated down by `--gap-close: 14vh` (invisible anyway, it is below the fold) and reaches `0` at
     70% of the first viewport scrolled → it moves ~1.2× page speed while entering. Combined with step 2, the
     distance between hero content and the "El problema" heading shrinks from ~(fold gap + 14vh) to the normal
     spacing.
   - Keep `pt-10 md:pt-14` (the final, "closed" spacing is the current one, which the user liked visually once
     scrolled). If the closed gap feels too tight, bump to `md:pt-20`.
   - `z-[1]` + its `bg-background` ensures the translated `Problem` paints over the fading hero, never under it.
   - The translated `Problem` overlaps the top of `Inventory` by ≤14vh only while `Inventory` is far below the fold
     (Problem is ~900px tall), so it is never visible.
4. **Optional visual separator** (improves the "two distinct screens" feel): a short scroll cue at the bottom of the
   hero — absolutely positioned at `bottom-6 left-1/2` inside the hero section, a small `ChevronDown` from
   `lucide-react` (already a dependency) in `text-brand/60`, gentle bounce (`animate-bounce` from Tailwind, wrapped
   in `motion-safe:`), `aria-hidden`, and it fades out with the same `parallax-hero-out` timeline
   (`animation-range: 0 20svh`). Hidden below `md`.

## Pitfalls / notes for the implementer

- `scroll-behavior: smooth` (`globals.css:8-10`) is compatible with scroll timelines; nothing to change.
- `animate-fade-in-up` uses `transform` + `forwards` fill (`globals.css:197-199`); keep parallax off that element.
- The `animation` shorthand resets `animation-timeline`; always write `animation-timeline` and `animation-range` after it.
- `view()` timelines track the element's own box; when the animated element is itself translated, use a wrapper
  as the subject (animate the child, observe the parent via a named `view-timeline` if jitter appears:
  `view-timeline: --media` on the wrapper, `animation-timeline: --media` on the child).
- Translated elements must not create horizontal overflow: hero gets `overflow-x-clip`; sections with blobs get
  `overflow-hidden`.
- Anchor links (`#demo`, `#producto`, `#lanzamientos`, `#servicios`, `#como-funciona`) use `scroll-mt-[68px]`
  (`section.tsx:35`). The `Problem` translate ends at 70svh so it is already `0` when any anchor lands; anchors
  below are unaffected.
- `next/image` with `fill` needs a positioned parent — keep `relative`/`absolute` on new wrappers in `ProblemSplit`
  and `FinalCta`.
- React Compiler is enabled; new client code (only `scroll-progress.tsx`, if chosen) must follow the hooks rules
  already used in `card-video.tsx`.
