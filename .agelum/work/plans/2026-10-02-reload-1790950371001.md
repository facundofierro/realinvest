# Plan: Wallet "continuous reload" fix (SPA behaviour)

Task: `.agelum/work/tasks/fixes/reload.md`

## Certainty assessment

**Level: High**

The captured evidence points to a specific cause, and that cause is in the code. `.agelum/work/tasks/context/26_10_02-105306-network.json` contains **no document requests** and **no 401s**. It only shows `GET /api/wallet/balances` + `GET /api/transactions` returning `200` every ~3.05 s. Every few cycles `/api/dashboard/projects` and `/api/wallet/holdings` are refetched too, and that only happens when the components using them remount. So the browser is **not** doing a real full-page reload. The app is **unmounting and remounting its entire tree** on every poll:

1. `useWalletBalances` (`refetchInterval: 3000`) runs on every desktop route, because `DesktopTopNav` uses it (`apps/wallet/src/components/desktop-top-nav.tsx:40`). The dashboard also uses it, together with `useTransactions` (`refetchInterval: 3000`).
2. Every refetch makes `useIsFetching() > 0`. `SplashScreen` (`apps/wallet/src/components/splash-screen.tsx:12-30`) then **replaces `{children}` with a full-screen black logo**. That unmounts the whole app (nav, page, dialogs, scroll position, images, local state).
3. When the fetch finishes, everything mounts again. Images reload, state resets and stale queries refetch. To the user this looks the same as a page reload, and it repeats every ~3 s. Navigating between pages causes the same full-screen splash, because new queries start fetching, so page switches feel like full reloads too.

The `window.location.assign("/login")` on 401 (`apps/wallet/src/lib/api-client.ts:38-40`) is a real SPA violation and could cause hard reload loops. It is not what the capture shows, but the plan still fixes it. A second issue, Auth.js `MissingSecret` / `ClientFetchError`, is environment-related and is handled as a separate step.

## Ambiguity assessment

**Level: Low**

The user has decided the open points (see "Decisions" below):
- The splash shows only on the very first load. After that, the app never covers or unmounts the tree; each section shows its own skeleton or loading state.
- Balances and transactions stop polling. They are fetched on mount and refreshed when the existing mutations invalidate them.
- A real expired session on web: on a 401, go to `/login?callbackUrl=…` through client-side routing (`router.replace`), not `window.location`.

Google OAuth sign-in/sign-out still needs a top-level navigation to Google. This is unavoidable and is not part of the "page switching" requirement.

## Decisions (confirmed with user)

| Topic | Decision |
|---|---|
| Splash screen | First load only. After the initial mount and first data load it never shows again. Background/navigation fetches use per-section loading states. |
| Polling | **Disable** `refetchInterval` for balances and transactions. Rely on fetch-on-mount + the existing mutation `invalidateQueries`. The KYC "pending" conditional poll stays (it only runs while a review is pending and has no visual effect once the splash is fixed). |
| 401 on web | SPA redirect to `/login?callbackUrl=<current path>` via `router.replace`, at most once, no `window.location`. |

## Root causes (ranked)

1. **[Confirmed, primary] `SplashScreen` unmounts the whole app on every fetch.** `apps/wallet/src/components/splash-screen.tsx:19-32` returns the overlay *instead of* `children` whenever `isFetching > 0`. It is mounted at the root in `apps/wallet/src/components/providers.tsx:25`, so it wraps every page, including `/login`.
2. **[Confirmed, amplifier] Global 3 s polling.** `apps/wallet/src/hooks/use-queries.ts:60-66` (balances, line 64) and `:82-84` (transactions, line 83). `useWalletBalances` is used by the always-mounted `DesktopTopNav` (`desktop-top-nav.tsx:40`) and `DesktopTokenTabs` (`desktop-token-tabs.tsx:166`), so the trigger fires on every page. `useKycApplication` polls every 3 s while KYC is pending (`use-queries.ts:198-205`).
3. **[Latent SPA violation] Hard navigation on 401.** `apps/wallet/src/lib/api-client.ts:38-40`: `window.location.assign("/login")` from inside a background fetch. If the cookie/JWT ever gets out of sync (see 4), a polled 401 triggers a full document reload. Then `apps/wallet/src/app/(auth)/login/page.tsx:10-12` (`redirect("/")`) and `apps/wallet/src/app/(dashboard)/layout.tsx:12-14` / `apps/wallet/src/proxy.ts:4-19` can bounce between pages.
4. **[Environment, secondary] Auth.js `MissingSecret`.** The console capture shows `[auth][error] MissingSecret` from the server, followed by `ClientFetchError` from `SessionProvider.getSession`. `apps/wallet/.env.local` does define `AUTH_SECRET`, so the dev server that produced the error most likely started without that env loaded (for example, launched from another cwd/process, or before `.env.local` existed). While it happens, `/api/auth/session` fails, `useSession` reports `unauthenticated`, and `auth()` can return null in server code. That feeds cause 3.
5. **[Not active] `RequireSession`** (`apps/wallet/src/components/require-session.tsx:7-12`) is only re-exported from `apps/wallet/src/index.ts:15` and is not used in the app tree. Leave it alone. If it is used later, it must use `router.replace` (it already does).

The other `setInterval`s in the task (`tokenization-page.tsx:152-164`, `stories-section.tsx:95-110`) only update local UI state and do not cause reloads. No change is needed.

## Implementation

### Phase 1 — Make the splash a first-load-only overlay (primary fix)

File: `apps/wallet/src/components/splash-screen.tsx`

1. Always render `{children}`. Never return the splash *instead of* children. Render the splash as a sibling overlay: `<>{children}{showSplash && <div className="fixed inset-0 z-[9999] …">…</div>}</>`. This way the tree is never unmounted, even while the splash is visible.
2. Replace the `isFetching > 0` condition with a one-shot "initial boot" flag:
   - `isMounted` (existing `useSyncExternalStore` at lines 13-17) is still required. It avoids a flash of content before hydration.
   - Add a `const [booted, setBooted] = useState(false)`. Once mounted and `useIsFetching() === 0` for the first time **after** at least one render, set `booted = true` in an effect, and never set it back to `false`. Optionally add a max timeout (for example 2–3 s), so a slow first request does not hold the splash forever.
   - `showSplash = !isMounted || !booted`.
   - Optionally fade out with the existing `transition-opacity duration-300`: switch to `opacity-0 pointer-events-none` before removing the overlay.
3. Keep the provider placement in `apps/wallet/src/components/providers.tsx:25` unchanged. With the overlay approach it is safe at the root, because the login page also gets only the one-time boot overlay.

Result: polling and page switches no longer unmount or cover the app.

### Phase 2 — Per-section loading states (replace what the splash was hiding)

The splash used to hide "first fetch" states for every page. Once it shows only at boot, pages reached by client-side navigation will render with `isLoading === true`. Make sure each page handles that state well (skeleton or inline spinner, never a blank screen or `$0` that jumps):

- `apps/wallet/src/components/pages/dashboard-page.tsx:46-80`: already reads `isLoading`/`isError` for projects, balances, holdings and transactions. Check that the render path actually shows a skeleton when `isLoading` (for example the balance card, "Oportunidades Destacadas" grid, and "Actividad Reciente"). Add `Skeleton` from `@repo/ui` where it only falls back to defaults (`= []`).
- `apps/wallet/src/components/desktop-top-nav.tsx:39-45`: the USDT amount defaults to `0`. While `isLoading`, show a small skeleton instead of `$0`.
- Review the other pages that read queries and add a loading branch where none exists: `assets-page.tsx:65`, `exchange-page.tsx:121`, `exchange-detail-page.tsx:139`, `project-units-page.tsx:56`, `withdraw-page.tsx:18-20`, `invest-page.tsx`, `project-detail-page.tsx`, `deposit-page.tsx`, `kyc-onboarding-page.tsx:15` (uses `isLoading` already).
- Use `isLoading` (first load only), **not** `isFetching`, so background refetches (invalidations, KYC pending poll) never show loaders.

### Phase 3 — Remove balances/transactions polling

File: `apps/wallet/src/hooks/use-queries.ts`

1. Remove `refetchInterval: 3000` from `useWalletBalances` (line 64) and `useTransactions` (line 83). Both become plain `useQuery({ queryKey, queryFn })` like `useWalletHoldings` (lines 68-73).
2. Freshness comes from the mutations that already invalidate these keys: `useCreatePosition` (lines 133-144), `useCreateWithdrawal` (lines 155-164), `useInvestPurchase` (lines 166-179) and `useSimulateDeposit` (lines 185-194). They need no change. With the global `staleTime: 60_000` (`providers.tsx:15`), navigating to a page after more than 60 s also refetches on mount.
3. Keep the conditional KYC poll in `useKycApplication` (lines 202-203). It only runs while `status === "pending"`, and once Phase 1 lands it has no visual effect.
4. If simulated custody transactions change status asynchronously (for example a withdrawal going from pending to completed in `@repo/fireblocks-mock`), the user sees the update on the next mount/invalidation, not live. This is accepted by the decision to disable polling.
5. Optional: in `apps/wallet/src/components/providers.tsx:13-18`, set `retry` so a failing 401 query does not retry 3×. For example, `retry: (count, err) => !(err instanceof UnauthorizedApiError) && count < 2`. This pairs with Phase 4.

### Phase 4 — Replace the hard 401 redirect with an SPA redirect

Files: `apps/wallet/src/lib/api-client.ts`, `apps/wallet/src/components/providers.tsx`, new small client component (for example `apps/wallet/src/components/auth-redirect-on-401.tsx`).

1. In `apps/wallet/src/lib/api-client.ts:38-40`, remove `window.location.assign("/login")`. Instead, notify subscribers without navigating:
   - Add a tiny module-level emitter in the same file (or `apps/wallet/src/lib/auth-events.ts`): `export function onUnauthorized(cb: () => void): () => void` and an internal `emitUnauthorized()`. Call `emitUnauthorized()` when the final response is `401` (after the native refresh attempt at lines 34-37).
   - Keep returning the response. Callers already throw on `!res.ok`, so react-query marks the query errored and no page reload happens.
2. Create `AuthRedirectOn401` (client component, `"use client"`), rendered inside `Providers` (`providers.tsx:23-27`, inside `AppSessionProvider` and `QueryClientProvider`):
   - `useRouter()`, `usePathname()`, `useQueryClient()`.
   - Subscribe with `onUnauthorized` in a `useEffect`. On the first event, if the current path is not `/login` and no redirect is already in progress (a `useRef` flag), call `queryClient.cancelQueries()`. This stops in-flight queries from firing more 401s. Then call `router.replace(`/login?callbackUrl=${encodeURIComponent(pathname)}`)`.
   - Reset the in-flight flag when `pathname` changes away from `/login`.
3. Native (Capacitor/Tauri) path: unchanged in behaviour. `refreshNativeAccessToken()` (`apps/wallet/src/lib/session/native-session.tsx:64-75`) still runs first. If it fails, `clear()` (line 63) sets `unauthenticated`, and the emitter triggers the same `router.replace`. That works for the static native bundle too.
4. Server-side gates stay as they are. They only apply to the initial document request or RSC requests, never to background polling:
   - `apps/wallet/src/proxy.ts:4-19` (already returns JSON 401 for `/api/*` and redirects pages with `callbackUrl`).
   - `apps/wallet/src/app/(dashboard)/layout.tsx:10-14`: change `redirect("/login")` to keep the `callbackUrl` consistent with the proxy. This is optional and defensive, because the proxy already handles it.
   - `apps/wallet/src/app/(auth)/login/page.tsx:10-12`: redirect to `redirectTo` (the validated `callbackUrl`, computed at line 15) instead of hard-coded `/`. Move line 15's computation above the check. When a user who is already signed in lands on `/login?callbackUrl=/exchange`, they go back where they were.
5. `apps/wallet/src/lib/session/web-session.ts:11-12` (`signIn`/`signOut` via next-auth redirects): **leave as is**. The Google OAuth handshake and cookie clearing need a top-level navigation. They are user-initiated, one-off actions, not page switches or polling.

### Phase 5 — Fix the Auth.js `MissingSecret` environment issue

1. `apps/wallet/src/auth.ts:29-34`: pass `secret: process.env.AUTH_SECRET` explicitly in the `NextAuth({...})` config. This makes the dependency visible. Also add a one-line dev guard near the top of the file, `if (!process.env.AUTH_SECRET) console.warn("[wallet] AUTH_SECRET is not set; sessions will fail")`, so a misconfigured launch is obvious in the server log instead of showing up as random `unauthenticated` flips.
2. Check that `.env.example` (repo root) lists `AUTH_SECRET`. `turbo.json` `globalEnv` already includes it. Mention in `apps/wallet/README.md` that the dev server must be started from `apps/wallet` (`pnpm --filter wallet dev` / `turbo dev`), so `apps/wallet/.env.local` is loaded.
3. No code depends on `RequireSession` (`apps/wallet/src/components/require-session.tsx`). Leave it alone.

## Acceptance criteria

- With the dashboard open and idle, the network panel shows no periodic requests and no `document` requests. The page is never covered or unmounted (scroll position, open dialogs and image elements persist). Balances/transactions refresh after a deposit, withdrawal, invest or trade mutation.
- Switching between Proyectos / Exchange / Tokenización / Assets causes no document request and no full-screen splash. New data appears through per-section loading states.
- A 401 from any API call navigates to `/login?callbackUrl=…` client-side, once, with no document reload. Polling stops after it.
- The server log no longer shows `MissingSecret` when the wallet dev server is started normally.
