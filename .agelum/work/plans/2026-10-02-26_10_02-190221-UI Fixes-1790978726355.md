# Plan: UI Fixes – Demo section skyline as large background with transparent fade

## Certainty assessment

**Level: Medium-High**

The component and image are located (`apps/landing/src/components/sections/final-cta.tsx:33-40`, `apps/landing/public/images/final-cta-skyline.webp`). The cause of the visible "faded" border is verified: the webp is an opaque RGB image (1920x800, VP8, no alpha) with a fade baked into the pixels toward a color that differs from the section background. Sampled pixels: corner (56,33,59), top-center (62,45,76), bottom-right (59,37,44), versus the section background `--color-dark-band: #241030` = (36,16,48) (`apps/landing/src/app/globals.css:119`). Because the fade color is baked in and doesn't match, no CSS can make it blend perfectly unless we use a CSS mask (which makes the image transparent at the edges regardless of baked pixels) — this is the recommended approach. Remaining uncertainty is visual tuning (mask gradient stops, opacity, how large the image should be) which needs a browser check.

## Ambiguity assessment

**Level: Low**

The request is fairly clear: the orange box covers the empty area of the left column below the skyline image (the right column holds the tall form, so the left column has a large blank space). The user wants the image shown much larger as a background for that area, with edges transparent-faded rather than a mismatched baked fade. Open decisions:
1. Scope of the "background": only the left column area (what the orange box encloses horizontally spans the full viewport width, vertically from below the heading to the section end), or the entire `#demo` section behind both columns/form. Plan default: full-bleed background of the `#demo` section, anchored to the lower-left, behind the content, with a mask fading to transparent on all edges. (Alternative: confined to the left column.)
2. Mobile: image is currently `hidden` below `sm`. Default: keep it hidden or show at low opacity on mobile — default to showing it as a subtle background on all sizes.
3. Image resolution: 1920x800 may look soft when enlarged; default is to accept it.

**Resolved with the user:** background spans the whole `#demo` section (full-bleed, bottom-left anchored); on mobile it is shown as a subtle low-opacity background (do NOT keep `hidden sm:block`). Remaining items are visual tuning only.

## Context / root cause

- `FinalCta` (`final-cta.tsx:7-45`): `<Section id="demo" tone="dark" containerClassName="grid items-start gap-14 lg:grid-cols-2">`. Left column: `SectionHeading` (15-21), optional WhatsApp CTA (22-32), then the skyline `<Image>` (33-40) with `mt-12 hidden h-auto w-full rounded-2xl sm:block`, limited to ~560px (`sizes`). The right column is `DemoForm` (`demo-form.tsx:105-` form with `rounded-[20px] ... bg-card`), much taller than the left, leaving a blank area under the image.
- `Section` (`apps/landing/src/components/section.tsx:15-44`): `<section>` has no `relative`/`overflow-hidden`, and the inner container is `max-w-[1180px] px-6`. The dark tone is `bg-dark-band` (`section.tsx:9`, color `#241030` at `globals.css:119`).
- Root causes of the visible rectangle: (a) the image is opaque with baked-in vignette to a brown/purple-ish color ≠ `#241030`, so its rectangular edge is visible; (b) `rounded-2xl` on an opaque image produces a visible box; (c) it is small and confined to the left column.

## Implementation steps

### Phase 1 – Make the section a positioning context
1. In `apps/landing/src/components/section.tsx:29-36`, no change needed to the tone logic, but allow passing `relative overflow-hidden` via the existing `className` prop. In `final-cta.tsx:9-13` add `className="relative isolate overflow-hidden"` to `<Section id="demo" ...>`.
2. The inner container div (`section.tsx:37-41`) needs to stack above the background: pass `containerClassName="relative z-10 grid items-start gap-14 lg:grid-cols-2"` (extend the current string at `final-cta.tsx:12`).

### Phase 2 – Move the image to a background layer with a transparent fade mask
3. Remove the `<Image>` at `final-cta.tsx:33-40` from the left column (and the `mt-12` spacing it provided).
4. Add, as the first child of `<Section>` (sibling before the container div — since `Section` wraps children inside the container div at `section.tsx:37-41`, either (a) add an optional `background?: ReactNode` prop to `Section` rendered before the container div inside `<section>`, or (b) place a `pointer-events-none absolute` wrapper inside the container that uses negative/inset positioning). Recommended: option (a), adding a `background` prop in `section.tsx:15-28` and rendering `{background}` right before the container div at line 37.
5. In `final-cta.tsx`, pass `background={<div aria-hidden className="pointer-events-none absolute inset-0 -z-10">…</div>}` containing:
   ```tsx
   <Image
     src="/images/final-cta-skyline.webp"
     alt=""
     fill
     sizes="100vw"
     className="object-cover object-bottom-left opacity-60 [mask-image:radial-gradient(ellipse_70%_70%_at_30%_70%,#000_30%,transparent_100%)] [-webkit-mask-image:radial-gradient(ellipse_70%_70%_at_30%_70%,#000_30%,transparent_100%)]"
   />
   ```
   - The mask makes all edges fade to genuinely transparent, so the section's `#241030` shows through (satisfies "transparent fade out"). Use both `mask-image` and `-webkit-mask-image` (Tailwind arbitrary properties) for Safari.
   - Remove `rounded-2xl` and `hidden sm:block` (or keep `hidden sm:block` if the decision for mobile is to hide).
   - Tune `opacity-*` (~0.5–0.7) so headings and the form remain legible; optionally add a overlay gradient `bg-gradient-to-r from-dark-band/80 via-dark-band/30 to-transparent` for text contrast over the heading area.
6. Because the baked-in vignette still sits in the image's outer pixels, the mask stop (`transparent 100%`) should fade fully before the image's edges, hiding the mismatched baked color. If the baked darkness still looks off in the center-ish areas, optionally regenerate `public/images/final-cta-skyline.webp` from its source without the vignette (not required; source not in repo — check `apps/landing/public/images` and `.agelum` for an original).

### Phase 3 – Visual verification of tuning (no automated tests)
7. Run the landing app (local.landing.realinvest.com via Caddy, see memory) and inspect `#demo` at desktop and mobile widths; adjust mask ellipse size/position, opacity, and `object-position` so the skyline appears large behind the left column / under the heading and fades out invisibly into `#241030` at all edges, including the section top/bottom boundaries with neighboring sections.

## Notes

- Do not add alpha by re-encoding unless needed; the CSS mask is sufficient.
