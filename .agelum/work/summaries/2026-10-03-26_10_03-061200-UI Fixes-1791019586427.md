# Summary: UI Fixes – smoother card hover + phone hover

The plan had Certainty Medium-High and Ambiguity Low, so I implemented without asking questions.

## Changes
- `apps/landing/src/components/sections/how-it-works.tsx`
  - Hover is now detected on the stable `<li>` (`group/step`) and applied to the inner card with `group-hover/step:`. This removes the hit-area flicker.
  - The transition list is `translate,box-shadow`, matching Tailwind v4's `-translate-y-1`, which sets the `translate` property. Before, the lift snapped while only the shadow eased.
  - Removed `will-change-transform`.
  - The icon uses `transition-[scale]` at 500ms, the same duration as the card.
- `apps/landing/src/components/phone-screenshot.tsx`
  - Now an outer `group/phone` wrapper (receives `className`, used for width) and an inner frame that lifts `-translate-y-1` with the same easing and duration as the cards.
  - New `frameClassName` prop for the shadow.
- `hero.tsx`, `investor-experience.tsx`, `buyer-portal.tsx`
  - Shadows moved to `frameClassName`, each with a slightly larger shadow on hover.

## Notes
- Tailwind v4's `hover:` and `group-hover:` variants only apply on `hover: hover` pointers, so touch devices don't get sticky hover. Motion is wrapped in `motion-safe:`.
- I didn't add the optional opacity-based shadow layer from Phase 1 step 4. Say so if the shadow still looks steppy.
- Verified with `tsc --noEmit` only. I haven't checked it visually in a browser, including whether the hero phone clips on lift.
