# fix image — launch-day fade blends into the dark band

Task: `.agelum/work/tasks/doing/fix-image.md`

## Problem

`apps/landing/public/images/launch-day.webp` was an opaque RGB image. Its left, right
and bottom edges faded to a baked-in brownish `#2C172A`, and its top edge was hard.
Over the `#241030` dark band this showed as a lighter rounded rectangle with muddy edges.

## Fix

- Made the image into an **RGBA WebP with a real alpha fade**. No new image was generated;
  the existing photo was processed with the new script `.imagegen/fade.py`:
  - A feathered rectangular alpha mask (smoothstep ramps: left x 150→400,
    right x 1420→1670, top y 0→80, bottom y 600→760). It reaches 0 inside the
    old baked vignette on every side, so the image has no hard edge or rectangle.
  - Pixels close to the old vignette color (`#2C172A`) are shifted toward
    `--color-dark-band` (`#241030`), so half-transparent edge pixels have no brown tint.
  - Output stays 1800×770 (~89 KB). Edge pixels are fully transparent, and the center is unchanged.
- `apps/landing/src/components/sections/launch-day.tsx`: removed `rounded-3xl` from the
  `<Image>`. It had no purpose now that the edges are transparent.
- Original kept for reference at `.imagegen/raw/launch-day-orig.webp`.

## Verification

- Checked a preview over `#241030` (`.imagegen/out/launch-day-preview.png`).
- `curl` of the static file and of `/_next/image` (with a webp Accept header) on the landing dev
  server (port 47313) returns the new RGBA image.
- Screenshot of the live `#lanzamientos` section at 1440px
  (`.imagegen/shots/launch-section.png`, made with `.imagegen/launch-shot.mjs`). The photo
  fades into the band with no visible rectangle or color mismatch.
- Note: the landing dev server keeps optimized images in `apps/landing/.next/dev/cache/images`
  (not `.next/cache/images`). It had to be cleared before the new image showed up.
