# Summary: UI Fixes – Demo section skyline as large background with transparent fade

Plan: `.agelum/work/plans/2026-10-02-26_10_02-190221-UI Fixes-1790978726355.md`
(Certainty Medium-High, Ambiguity Low with decisions already resolved, so implemented directly.)

## Changes

### `apps/landing/src/components/section.tsx`
- Added an optional `background?: ReactNode` prop to `Section`. It renders inside `<section>`, just before the content container, so sections can have a decorative layer that spans the full width.

### `apps/landing/src/components/sections/final-cta.tsx`
- Removed the small skyline `<Image>` from the left column (it was `mt-12 hidden ... rounded-2xl sm:block`).
- `#demo` section now uses `className="relative isolate overflow-hidden"`, and its container uses `relative z-10 ...` so content stacks above the background.
- Added a full-bleed background: a `pointer-events-none absolute inset-0 -z-10` wrapper holding `next/image` with `fill`, `object-cover object-[25%_100%]`, `opacity-35` (mobile) / `lg:opacity-55`.
- The fade uses a real CSS mask on the wrapper (`skylineMask`), not the image's baked-in vignette. Two linear gradients are intersected (`mask-composite: intersect` / `-webkit-mask-composite: source-in`):
  - vertical: transparent → opaque 40%–72% → transparent at the bottom edge
  - horizontal: transparent → opaque 12%–55% → transparent at 92%
  So every edge fades to true transparency over `#241030`. The opaque image's mismatched vignette color and its rectangle are no longer visible.

## Deviation from plan
- The plan suggested a single radial-gradient mask. I tried it first in the browser: the bottom and left edges of the section still ended in hard lines (visible against the footer) because the ellipse reached past the section edges. I replaced it with two intersected linear masks, which fade all four edges reliably.
- No image regeneration was needed (fal/genmedia not used). The CSS mask was enough, as the plan expected.

## Verification
- Visually checked on the running landing dev server (`localhost:47313`) at desktop width (~1728px): the skyline appears large behind the left column below the heading, the heading and lead stay legible, and it fades out into the band on the top, bottom (no seam against the footer), left and right.
- Mobile (390px, emulated with an iframe because the window resize didn't apply): the image shows as a subtle low-opacity background, mostly behind the form, as decided.
- `eslint` on both files and `tsc --noEmit` for `apps/landing` pass.

## Possible follow-ups (tuning only)
- Faint buildings are visible to the right of the form on wide screens (the horizontal fade runs from 55% to 92%). Pull the `92%` stop in if that's unwanted.
- Adjust opacity / `object-position` if a different part of the skyline should be emphasized.
