# Summary: Playwright e2e use-case tests (wallet + admin, providers mocked)

Plan: `.agelum/work/plans/2026-10-02-playwrite-test-2-1790965585223.md`
(Certainty Medium-High, Ambiguity Low, so implemented without extra questions.)

## Result

`pnpm e2e` runs **77 tests, all passing**, twice in a row from a fresh migrate + seed
(the second run checks that re-seeding works after trades and custody state exist).
The KYC spec also passed 30/30 with `--repeat-each=3`. `tsc --noEmit` is clean for
`apps/wallet`, `apps/admin`, `apps/e2e`, `packages/ui` and `packages/db`.

## Infrastructure (Phase 0)

- **Seed is a full reset** (`packages/db/src/seed.ts`). It now deletes, in FK-safe
  order, `trades`, `kyc_applications`, all `fireblocks_*` tables and the native auth
  tables, as well as the tables it deleted before. Re-seeding after an exchange fill
  no longer fails.
- **Shared DB for both apps.** `apps/e2e/env.ts` defines `DB_URL` (the dev DB by
  default; override with `E2E_DATABASE_URL`). `playwright.config.ts` passes
  `DATABASE_URL` to both web servers, plus `E2E_AUTH_BYPASS=1` and
  `AUTH_URL=<wallet>` to the wallet.
- **Global setup** (`apps/e2e/global-setup.ts`) runs `db:migrate` then `db:seed`
  (skip with `E2E_SKIP_SEED=1`). It checks through `admin.dashboard.stats` that the
  admin sees the seeded DB and fails with a hint if not. It then saves the demo-user
  session.
- **Multiple identities** (`apps/wallet/src/auth.ts`). The `e2e` Credentials
  provider accepts `userId`: `demo-user`, or `e2e-[a-z0-9-]{1,64}` users created on
  demand. It stays env-gated and is never enabled in production.
- **Config.** Expect timeout 10 s, `serviceWorkers: "block"`, and an extended
  wallet `testMatch`. Identity is chosen per spec, not per project.

## App bugs found and fixed by the suite

1. **KYC wizard skipped the review step and auto-submitted**
   (`kyc-wizard.tsx`). React reused the "Siguiente" button DOM node as the
   `type="submit"` button, so the click on step 3 submitted the form. Fixed by giving
   the two buttons distinct keys.
2. **Session `kycStatus` never refreshed after a KYC submit**
   (`kyc-onboarding-page.tsx`). In next-auth beta, `update()` with no arguments only
   GETs the session. The JWT never received `trigger: "update"`, and the effect
   looped on GET `/api/auth/session`. Fixed with `update({})`.
3. **The deposit KYC-blocked dialog had no rejection reason**
   (`lib/kyc-guard.ts`). `checkKycApproved` now returns `{ status, rejectionReason }`
   and the 403 includes the reason. All 5 callers are unchanged.
4. **The withdraw status chip stayed on "pendiente"**. `useTransactions` never
   refetched (`refetchOnWindowFocus: false`). It now accepts a `refetchInterval`;
   the withdraw page and `InvestConfirmDialog` poll every 1 s only while their own
   operation is in flight. Without this, "Compra completada" also never appeared.
5. **setState-in-render on `/project/:id/units`** (`splash-screen.tsx`, decision
   D4). SplashScreen's query-cache listener called `setBooted` synchronously. A
   `useQuery` mounting during another component's render fires that event. The
   check is now deferred with `setTimeout`.
6. **Trade errors were swallowed** (unhandled rejection, no feedback).
   `createPosition` now throws `walletApiError` with a `code`. `TradeDialog` gained
   an `error` prop (`role="alert"`) and Spanish copy for each error code. Wired in
   `exchange-detail-page.tsx` and `desktop-token-tabs.tsx`.
7. **Unknown exchange symbol showed "Failed to fetch order book"**. The detail page
   now reports "Token not found" first.
8. **Units page purchase had no KYC gate**. The tokenized INVERTIR now uses
   `useKycGate` and `KycBlockedDialog`, like every other invest or trade entry point.
9. **Admin: the Select dropdown opened behind the dialog**, so the property status
   could not be picked. The shared Dialog is `z-[100]`/`z-[110]`;
   `SelectContent` and `DropdownMenu` content moved from `z-50` to `z-[120]`
   (`packages/ui`).
10. **Admin: the edit property form opened empty**. `PropertyFormDialog` kept its
    initial `useState`. It is now keyed by project id.
11. **Admin: `/chat` hydration mismatch**. Mock timestamps use `Date.now()` at
    module load. Added `suppressHydrationWarning` on the timestamp elements.

Small accessibility additions used by the tests: `aria-pressed` on the exchange
timeframe buttons and on the chart view selector.

## Deviations from the plan / known gaps (not fixed)

- **Favorites are not implemented.** `lib/api/market.ts` hardcodes
  `isFavorite: false` and there is no DB column or toggle. The test asserts that the
  Favoritos tab is empty.
- **The wallet chat and admin chat are local stubs.** There is no assistant reply,
  and admin send only clears the input. The tests assert the current behavior.
- **The admin does not serve the seeded project images** (`/projects/*.png` live
  in `apps/wallet/public`). The smoke suite has a narrow, commented exception for
  those 404s in `helpers/smoke.ts`.
- **Test-side race, documented in the README.** Polling `/api/auth/session` from
  the test while the page POSTs a session update can overwrite the new JWT cookie
  with the old one. The helpers wait for the page's own update response
  (`waitForSessionKyc`).
- **Pre-existing lint findings were left alone.** `kyc-onboarding-page.tsx:16`
  (`setMode` inside an effect) and unused imports in `project-units-page.tsx`.
- `apps/admin/.env.local` was not created (it is gitignored). The README documents
  it, and the Playwright-started admin gets `DATABASE_URL` from the config.
