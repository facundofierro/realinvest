# KYC onboarding UI flow — summary

Implemented the `/kyc` onboarding flow and its supporting KYC API integration.

## Changes made

- Extended the KYC provider identity contract with applicant PEP and sanctions declarations; the deterministic mock now rejects those self-declarations before document-name rules.
- Added wallet dependency/config wiring for `@repo/providers-kyc`, React Hook Form, Zod, and resolver support.
- Added the singleton KYC provider, shared submission schema, authenticated `GET`/`POST /api/kyc` route, client API functions, and TanStack Query hooks with pending-status polling.
- Built a five-step ES/EN KYC wizard: identity, document name collection, beneficial owners, PEP/sanctions, and review. Files are intentionally represented only by their names, matching the mock provider contract.
- Added pending, approved, and rejected status views, including retry/prefill behavior and session refresh after a status transition.
- Added `/kyc` navigation CTAs to both account menus and a status-aware dashboard banner.

## Verification

- `pnpm install` completed successfully. It reported existing peer-dependency warnings.
- `pnpm --filter wallet exec tsc --noEmit` showed no KYC-related errors after the form integration was adjusted. The command still reports numerous pre-existing strict TypeScript errors in unrelated wallet/backend screens.
- `pnpm --filter wallet build` was started but stalled while Next.js compiled; the initiated build process was terminated after several minutes. `git diff --check` passes.
