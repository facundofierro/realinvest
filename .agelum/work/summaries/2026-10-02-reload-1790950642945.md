# Summary: Wallet "continuous reload" fix

Plan: `.agelum/work/plans/2026-10-02-reload-1790950371001.md` (Certainty High, Ambiguity Low, so no pre-implementation questions)

## Root cause
`SplashScreen` replaced the whole app tree with a full-screen logo whenever any react-query query was fetching. Balances and transactions polled every 3 s, so the whole app unmounted and remounted every ~3 s, which looked like a page reload.

## Changes

### Phase 1: splash only on first load
- `apps/wallet/src/components/splash-screen.tsx`: `children` are always rendered and the splash is now a sibling overlay. It shows until the first data load settles. It detects this by subscribing to the query cache and checking `queryClient.isFetching() === 0`, with a deferred first check and a 2.5 s maximum. It then fades out (300 ms) and is removed. It never shows again.

### Phase 2: per-section loading states
- Most pages (dashboard, assets, exchange, exchange-detail, project-detail, project-units, deposit, kyc) already had `isLoading` branches.
- Added `Skeleton`s (`@repo/ui/components/ui/skeleton`) where the UI fell back to defaults:
  - `desktop-top-nav.tsx`: USDT balance (previously showed `$0` while loading).
  - `pages/withdraw-page.tsx`: "Disponible" amount (the `<p>` became a `<div>` to avoid invalid nesting).
  - `pages/invest-page.tsx`: project grid placeholder cards.

### Phase 3: polling removed
- `apps/wallet/src/hooks/use-queries.ts`: removed `refetchInterval: 3000` from `useWalletBalances` and `useTransactions`. Data stays fresh through the existing mutation `invalidateQueries`. The conditional KYC "pending" poll is kept.
- The optional `retry` tweak was skipped. API helpers throw a generic `Error` on `!res.ok`, so a 401 can't be identified there. `cancelQueries()` on redirect stops pending retries instead.

### Phase 4: SPA redirect on 401
- New `apps/wallet/src/lib/auth-events.ts`: `onUnauthorized` / `emitUnauthorized` emitter.
- `apps/wallet/src/lib/api-client.ts`: `window.location.assign("/login")` replaced with `emitUnauthorized()`. The native token refresh still runs first.
- New `apps/wallet/src/components/auth-redirect-on-401.tsx`: on the first 401 it calls `queryClient.cancelQueries()` and then `router.replace('/login?callbackUrl=<path>')`. A ref guard makes sure this happens only once. The guard resets after leaving `/login`.
- `apps/wallet/src/components/providers.tsx`: mounts `<AuthRedirectOn401 />` inside the QueryClientProvider.
- `apps/wallet/src/app/(auth)/login/page.tsx`: when the user is already signed in, it redirects to the validated `callbackUrl` (protocol-relative `//` URLs are rejected) instead of `/`.
- `(dashboard)/layout.tsx` was left unchanged. The server layout doesn't know the request path, and `proxy.ts` already adds `callbackUrl`.
- `web-session.ts` signIn/signOut were left as top-level navigations, because OAuth requires them.

### Phase 5: AUTH_SECRET
- `apps/wallet/src/auth.ts`: passes `secret: process.env.AUTH_SECRET` explicitly and logs a `console.warn` when it is missing.
- `apps/wallet/README.md`: documents that `.env.local` must be in `apps/wallet` and that the dev server must be started through the wallet package. Explains the `MissingSecret` symptom.
- The root `.env.example` already lists `AUTH_SECRET`, and `turbo.json` `globalEnv` already includes it.

## Verification
- `tsc --noEmit` (apps/wallet): passes.
- ESLint on changed files: no errors. The two warnings already existed (`<img>` in the top nav, an unused `Project` type in invest-page).
- Browser (signed in, `https://local.wallet.realinvest.com/`):
  - Idle dashboard for ~10 s: no `/api/*` requests and no document requests (only two lazy images).
  - Client-side navigation to `/tokenization`: a single `?_rsc=` fetch plus chunks. A `window` marker survived (no document reload) and no splash appeared.
- Not tested live: the 401 redirect path (it would mean invalidating the real session) and the native (Capacitor/Tauri) flow.

## Notes / residual risk
- If the auth cookie gets out of sync (the server page gate accepts it but `/api/*` rejects it), a client-side `/login` → callbackUrl → 401 bounce is still possible. It no longer involves document reloads. Fixing the AUTH_SECRET env issue removes the known trigger.
